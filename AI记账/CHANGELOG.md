## 设计取舍（答辩口径 · 与"可维护性"相关的刻意决策）

- **单文件 · 零构建 · 零依赖**：`AI记账.html` 内联全部 JS/CSS，双击即跑、断网可用、评委现场演示不依赖网络或 npm。这是相对"拆分多文件 / 引入打包器 / 上 TypeScript"的主动取舍——后者会削弱"现场可演示"这一核心链路。
- **运行时模块系统（非"纯靠约定"）**：各业务域以 UMD 形式挂到 `window.AJ.*`（如 `data.js→AJ.data`），由 `app.js` 在 IIFE 顶部以 `var X = global.AJ.x` 显式绑定编排。命名空间是文档化的契约（见 `app.js` 文件头），加载顺序由内联 `<script>` 块顺序保证。
- **未引入 TypeScript / 打包器**：与上面同因。重构风险在"已冻结的参赛交付物"前提下不成立；仅当项目转为长期演进产品时才建议引入类型系统与构建链。

## 2026-11-04 · 惠寻进 App 教学：京东自有品牌也算一个「省钱渠道」

用户给了一份现成的知识库条目（惠寻 = 京东自有品牌、直连工厂、1 件包邮、9.9 元档），要求作为新款加进 App 教学。

严格说惠寻不是一个独立 App，它是京东站内的品牌馆 —— 但对学生来说，「纸巾去京东搜惠寻」和「买药上美团」是同一类动作：**一个具体的省钱入口**。所以按既有卡片规格收进「日用百货」，而不是塞进京东那 4 条技巧里当附注（塞进去大概率没人翻到）。

## 2026-11-03 · 树洞不能把人撂在那儿：愿望句要接住，还要给方向

用户截图：「我真的很想去北京旅游」→「别骂自己啦。钱已经花了，自责也换不回来。今晚先好好睡一觉……」。原话：「这说完也要分析呀」。

一句回复里有两个错：

1. **预设了他没做过的事**：他没花钱、没自责，只是在说一个愿望。安慰模板默认「你刚花了钱在自责」，套上去就是在跟他没说过的事说话 —— 比答偏更伤人。
2. **说完就完了**：接住情绪之后没有任何出口，用户被留在原地。

### 根因

`comfort()` 的文案池只有一种预设（花完钱在自责），`sendToAssistant` 的树洞分支 `addAIMessage` 完就 `return`，既没有下一步、也没有可点的去处。

### 四处改

| 改哪 | 怎么改 |
|---|---|
| 文案分型 | 新增 `isWish()`：`想去 / 打算去 / 攒钱去` 与 `想买 / 想换 / 想入手` 分两池，各配三种语气；**带「后悔 / 没用」的不算愿望**（「想去旅游但钱花光了，好后悔」主体仍是后悔，先安慰） |
| 愿望文案 | 想去 →「车票 / 住宿 / 门票」三笔；想买 →「本体 / 配件 / 维修」三笔。都只给方向、**不报数字** —— 本地没有实时票价，编一个数比不给更坏；要数就去攒钱面板或云端 |
| 出口 | 树洞结尾挂 2 个真能点的按钮：愿望句 →「我想攒钱去旅行 / 看看这月的账单分析」；情绪句 →「看看这月的账单分析 / 设置预算」 |
| 豁免 | 新增 `comfortExit()`：按钮是 `data-cmd` 直接重发一句话，会再进一次情绪判断。不豁免的话，用户点「我想攒钱去旅行」回来的还是安慰 —— **按钮成了骗人的装饰**。限制三条防误伤：超过 16 字不算（那是在倾诉）、带情绪词不算、只认操作白名单 |

### 提示词也补了两条（云端侧同一条规矩）

- 接住之后必须留一条能往下走的路，不许停在安慰：想去 / 想买就把钱拆成三笔，或者约「明天一起看账」。
- 不许假设用户已经买过、已经花了钱。「我真的很想去北京」= 还没去。

### 顺手补的安全口子

`CRISIS` 加了「想去死 / 活不下去」——「我真的想去死」里有「想去」，不拦就会被当成旅行愿望去拆车票。现在它走危机兜底，回「我在的」。

### 验证

- 规则层 **172/172**（+5：愿望三风格 / 想买三风格 / 愿望判定边界 / 愿望不被安慰吃掉 / 危机优先于愿望）。
- 端到端 **51/51**（+2：锁树洞说想去北京不回「钱已经花了」且留 2 个出口；点「我想攒钱去旅行」真的进攒钱引导，不再被安慰吃掉）。
- 截图 `_shot/shot_voicetone.py` 第五张：`voicetone_5_wish.png`。

## 2026-11-03 · 说话方式 × 语言风格：两层开关，不是两个孤岛

用户原话：「也要结合用户选择的AI语言风格」。

上一轮把「说话方式」做成了可锁的四档（自动 / 聊天 / 拆解 / 树洞），但只做了一半：**方式换了，口气没换**。设置里选了「铁面教练」，18 块的黄焖鸡回执还是「✅ 记好啦！很标准嘛，继续保持～」；锁了树洞，接住的仍是「摸摸头，别自责啦 🫂」。两层开关各自成立，叠在一起就露馅 —— 用户会认为「风格那个选项是假的」。

### 一句话说清两层

| 层 | 谁负责 | 改什么 | 不改什么 |
|---|---|---|---|
| 说话方式（`voice.js` 的 chat / breakdown / comfort） | 聊天框上方那颗键 | 说几句、要不要算账、出不出卡 | 事实与结论 |
| 语言风格（`tone.js` 的 gentle / strict / rational / custom） | 设置 →「它怎么说话」 | 用什么口气、称呼、句子长短 | 金额、拦截线、该说的坏消息 |

### 三处落地（缺一处就会「一半生效」）

1. **本地文案**（`chatBill(ctx, tone)`）：四种预算状态 × 三种风格。数字先算好再选腔调，所以换风格不会把「还剩 300 / 8 天」说丢 —— 这是本轮唯一的硬约束。
2. **表头 + 树洞文案**（`headerSet(seed, forced, tone)` / `comfort({raw, tone})`）：教练档两套「📉 账在这儿 / 🚫 别踩」，数据档两套「📊 数据口径 / 📌 风险提示」；树洞三套，教练档不哄、数据档不煽情，但**都不算账、都不指责人格**。
3. **云端提示词**：非自动档的标题直接写成「【说话方式·树洞 × 说话风格·铁面教练】」，并附一句**成品示例**（不是形容词）。模型看到「树洞 + 教练」很容易两边各取一半，给它一句现成的话，它才知道边界。

### 两个刻意的取舍

- **`custom`（用户自写人设）在本地文案里回落温柔学姐**：本地句子是写死的，用户那 120 个字只有云端读得到。硬编一个「自定义腔」既猜不准，又容易把自称写错。云端会照用户设定演，本地只出最中性的骨架。
- **危机句不随风格变化**：`我撑不住了` 一律回同一句（含「我在的」「学校心理中心」），选了铁面教练也不变冷。语气是排版问题，不是把人推开的理由 —— 这条写进了 `voice.js` 的注释，防止以后有人「顺手统一一下风格」。

### 界面

模式键的前缀跟着风格走：`说法` → `说法·教练` / `说法·数据` / `说法·人设`，锁定后变 `锁定·教练`。
顺手修了一个真 bug：原先「已锁定」是挂在尾巴上的 `::after`，前缀一变长就在 390 宽下被横滑切掉半截，用户看到的是一个残字。改成并进前缀后总长不变，信息还更清楚。

### 验证

- 规则层 `test/eval_rules.js`：**167/167**（新增 7 条：三风格文案 / 超支分支 / 语气归一 / 树洞三风格 / 危机句三风格一致 / 表头三风格 / 锁拆解×教练档）。
- 端到端 `test/eval_e2e.js`：**49/49**（新增 2 条：教练档树洞不出现 🫂、教练档记账不带「记好啦」）。
- `rebundle.py --check`：31 模块 + 1 样式，漂移 0 块。
- 截图：`_shot/voicetone_1_bar.png`（说法·教练）、`voicetone_2_bill.png`（记上了…稳住）、`voicetone_3_comfort.png`（锁定·教练 + 树洞）、`voicetone_4_set.png`（设置页「当前：树洞｜措辞：铁面教练」）。

## 2026-11-03 · 给「说话方式」装一个键：四档可锁，自动仍是默认

用户原话：「三种说话模式要有个键调节」。

上一轮把三模式（聊天 / 拆解 / 树洞）做成**自动判定**，还特意写了「界面上不放开关，因为让人选『我现在需要安慰还是算账』本身就很机械」。这个判断只对了一半：**默认自动**是对的，**没有出口**是错的。判定再准也有它猜不到的时候 —— 失恋那天用户就是想听人说两句，不想看 1662 元的房租拆解。

### 四档，两个入口

| 档位 | 行为 |
|---|---|
| 🎚️ 自动（默认） | 沿用原来的信号判定：情绪 > 结构/大额 > 聊天 |
| 💬 聊天 | 记账一律一句话收尾；情绪句仍走树洞 |
| 🔍 拆解 | 记账一律正式汇报（收据 + 余额 + 教练话）；表头固定「🔍 拆解一下」那套，不再轮换 |
| 🫂 树洞 | 一律先接情绪：不算账、不出卡、不入账，**哪怕句子里有「房租 1500」** |

入口两处、同一份 DOM：聊天输入框上方一排（`#voiceModeBar`）+ 设置页「说话方式」卡（`setGroupVoice`）。持久化在 `settings.voiceMode`，白名单归一，未知值回落 auto。

### 生效链路（五个必须改的点）

1. **`classify(raw, ctx, forced)`**：手动档位排在所有信号之前。用户按了「树洞」，句子里有「怎么省钱」也不许被拽回去算账 —— 否则那颗键就是装饰。
2. **情绪拦截**（`sendToAssistant` ①.03）：锁树洞时**跳过「有没有开销场景」这道门**。自动档下「房租 1500 好焦虑」会先算账（这是对的）；锁了树洞还这么干，就是在用户明确说「别算」之后继续算。
3. **记账回执**（`reportCommitted`）：自动档阈值仍是 300 元；锁「聊天」放宽到 1000（千元以上仍走正式汇报，那种账不该被一句话打发）；锁「拆解」则不论金额一律正式汇报。
4. **表头**（`headerSet(seed, forced)`）：锁拆解固定第二套。轮换的前提是「我替你挑」，用户自己挑了还轮换，像没听指令。
5. **云端提示词**：新增【说话方式·X】段（仅非自动时注入）。本地只拦得住「短句 + 单金额」的快路径，超过 14 字就走云端 —— 档位只写在本地分支里，用户锁了树洞却发现长句子还是被算了一通账，键就成了摆设。

### 一条硬边界：档位不凌驾安全规则

写测试时先试了「锁聊天 → 500 元外套也只给一句话」，结果那笔**先被冷静期拦下了**，根本没走到回执。这不是 bug，是正确行为：用户把说话方式调成「简洁」，不等于授权跳过冲动消费拦截。档位管**怎么说**，不管**能不能花**。

### 顺手修掉一个测试真 bug

e2e 取「最后一条 AI 回复」一直是 `document.querySelectorAll('.bubble.ai')` 的最后一个。但记账回执的正文气泡与收据卡、余额概览、教练话在 `.msg-body` 里是**兄弟节点**，只读气泡等于只看半条消息 —— 所以「正式汇报带没带余额明细」这类断言长期是瞎的（这次写新用例才暴露：回复只显示「【记账成功】记上了」，余额明细明明在同一个 msg-body 里）。
改为按「最后一条非『我』的 `.msg-row`」取整条，`r.reply` 才等于用户真正看到的那条。连带修了「大额拦截」用例的措辞词表（漏了「不记 / 离谱 / 真实金额」，拦截其实发生了却被判成没拦）。

**验证**：规则层 **160/160**（新增 6 条：三档强制优先、`normForced` 容错、锁拆解固定表头、四档元信息）；端到端 **47/47**（新增 2 条真机用例：锁拆解 / 锁树洞，用新加的 `preJs` 钩子在发消息前点键）；双产物 `rebundle --check` **31 模块 + 1 样式，漂移 0**；截图 `_shot/shot_voicemode.py` 三张（idle / locked / set）。

## 2026-11-03 · 答非所问两处：把「我想了解」当成「我做了」+ 纠正后不接上下文

用户实测两轮截图：

> 我：双十一怎么玩京东
> AI：**凑单防反薅雷达启动！**「满减的门槛是商家算好的…」（把提问当成了复盘）
> 我：不是，我要了解京东
> AI：「京东省的套路不多，但能省出几十到几百…」（没有接上一轮，也没接「双十一」）

两个问题都不是文案问题，是**意图识别粒度**和**纠正处理**没建模。

**A. 「我做了」vs「我想了解」：词袋分不清，只能靠动作词硬分**

`双十一` 是 3 字词，比任何场景词都长，于是「双十一怎么玩京东」「双十一套路多吗」「双十一有什么优惠」全部命中 `promo`，被答成「你被反薅了」。而 `promo` 的语义是**行为复盘**（算净多花多少），完全接不住**攻略咨询**。

修法是把两件事拆开，而不是给 promo 加一句文案：

- 新增场景 `playbook`（平台攻略，🗺️）：「优惠是三层叠的」+「补到下一档划不划算」的临界点算法。
- `promo` 加**第一人称已完成动作门禁**：必须命中 `凑单|凑了|硬买|多买|反薅|为了凑|尾款|下单了|付了…定金` 之一，否则一律改判 `playbook`。
- 词表只收「大促名 / 平台机制名」（`双十一 / 618 / 领券 / 价保 / 优惠券`），**不收通用方法论词**——第一版收了 `怎么买便宜`（5 字），立刻把「买衣服怎么买便宜」从 `clothes` 抢成攻略，「买药怎么买便宜」同理，规则层直接红两条。
- 平台名 + 疑问语气也改判：`拼多多百亿补贴靠谱吗` 原本被判成 `digital`（问的是平台，不是那台机器）。
- 有预算时给临界点而不是「多领券」：500 吃 1 档满减（-50），补到下一档要 100 → **补 100 且只减 50，判「别补」**；280 差 20 减 50 → 判「可以补」。这条是真判断，不是话术。

**B. 用户说「不是」时，先认账再答**

原提示词 21 条里没有任何一条管**纠正信号**（「不是 / 不对 / 我没问这个 / 答偏了」）。缺失的后果是模型装作没听见，直接换一套说辞——用户体感就是「上下文联系不行」。

- 提示词新增第 22 条：纠正必须三步走（先认下 → 复述他真正要的 → 再答），且上一轮的语境（时间、地点、对象）要接着用，不许当全新对话从零开始。
- 第 16 条补一句：不许先给平台下「套路不多 / 没什么可省的」这种空评价再列一堆方法——前后会打脸。截图里那句「京东省的套路不多，但能省出几十到几百」就是典型。
- 本地也接了一层：`svAnswer` 在纠正时补一句 `.sv-lead`「刚才答偏了：我拿「大促凑单」的框子接的，其实你问的是另一件事。」

## 2026-11-03 · 说话方式三模式（voice.js）：不再每条回复都套「计算 → 常识 → 避坑」

用户反馈很直接：场景内容是对的，但**每一条都长成同一个样子**——雷达启动、账单透视、生存常识、避坑指南、A/B 两选项，像模板填空，不像人说话。要求「有血有肉的学长/学姐」，按情绪和场景在三种模式间切换：

- **模式一 聊天式**（日常小额记账、吃喝玩乐、轻度吐槽）：像发微信，短句、带情绪词，不用表格和分割线。
- **模式二 硬核拆解**（大额购物、租房、数码、水电话费异常）：可以分层长答，但别每次都用一模一样的 Emoji 标题。
- **模式三 情绪树洞**（超支崩溃、冲动消费、深夜 emo）：放弃算账与说教，字数越少越好，先给情绪价值。

### 改法

- **新建 `voice.js`（UMD，纯函数，零 DOM / 零存储 / 零网络）**：只负责「回答**形态**」路由，与既有 `tone.js`（语气预设 gentle / strict / rational，管**文案措辞**）是两个正交维度，互不覆盖。`classify(raw, ctx)` 返回 `chat | breakdown | comfort`，`chatBill(ctx)` / `comfort(ctx)` / `headerSet(seed)` / `sep()` 供上层拼装。
- **判据按优先级三级**：情绪树洞 > 硬核拆解 > 聊天式。落在 `comfort` 的条件是**情绪词 && 无分析词**（`EMOTE` / `IMPULSE`+`REGRET`）且 `!ANALYTIC`——「我好焦虑，怎么省钱啊」仍然算账，不会被安慰话术糊弄过去。跨过 `breakdown` 的门槛是**结构化场景**（租房 / 数码 / 水电 / 话费 / 理发 / 健身 / 二手）或 `金额 ≥ 300` 或命中结构词表。
- **模式一接进记账回执**：`reportCommitted` 的支出分支里，`amount < 300` 且 `VOICE.chatBill` 可用时，用「✅ 记好啦！18 块的黄焖鸡很标准嘛。这月生活费还剩 300（还有 8 天），节奏不错，继续保持～」替掉原来的「理财专家说」点评卡（超支 / 见底 / 日均 < 30 三种分支各有说法），避免一句话里叠两层口吻。同屏的**余额概览也一并省掉**——那句话里已经说了「还剩多少、还有几天」，再摆一张明细台账就是同一个数字说两遍（真机截图看着像两份账单）。收据卡保留：它是凭证，还带撤销入口。
- **模式二不再千篇一律**：`chatHtml` 新增 `opts.headers` 覆盖三段表头；`voice.js` 内置四套同义表头（🧮 账单透视 / 🔍 拆解一下 / 🧾 算一笔账 / 🔎 掰开揉碎 …），按 `hash(scene + raw)` 取模轮换。同一句重复问会稳定拿到同一套（确定性可测），不同场景之间则会换脸。
- **模式三做成前置拦截**：`sendToAssistant` 在 `priceResume` 之后、`priceTakeOver` 之前插入情绪判断。命中且 `SV.fromText` 判不出具体开销场景时，直接回温柔短句并 `return`，**不入账、不弹卡、不追问**；危机词（撑不住 / 不想活 / 讨厌自己 …）走专用兜底，引导找学校心理中心或信得过的人。
- **段落分隔改用 `.vo-sep`**：原文靠标题 Emoji 分隔模块，现在标题会轮换，改用一条 `border-top: 1px dashed` 的 `div`（不用 `<hr>`，避免被全局 hr 样式带偏，已 `aria-hidden`）。
- **新增 `usedbuy` 场景**（买二手掌机）：`secondhand` 原本是「卖闲置被到手刀」，用户说「想买个二手 switch 1200」会被答成卖家的坑。词表只放机器名（switch / ps5 / kindle / 二手），在 `detect` 里用 `buying && !selling` 改判，buying 才走 `usedbuy`（版本坑 OLED/续航/老款、配件坑底座手柄电源 +200、账号坑数字版游戏易找回），selling 仍走「到手刀」。

### 测试

- 规则层 `test/eval_rules.js`：108 条增至 **120/120** 通过；新增 12 条覆盖三模式分类、`chatBill` 形态（含 18 块 + 剩余 300 + 无「【记账成功】」）、`comfort` 不算账、危机兜底、`headerSet` 确定性且有变体、`chatHtml` 自定义表头带 `vo-sep`、`usedbuy` vs `secondhand` 改判。

### 踩到的坑

1. **表头轮换打断了既有断言**：一批 e2e 用例写的是 `[/账单透视/.test(card)]`，轮换后随机挑到「拆解一下」就红。全部改为变体集合正则 `/(账单透视|拆解一下|算一笔账|掰开揉碎)/`。教训：**凡是会被「刻意打散」的文案，测试就不能断言字面值**。
2. **`EMOTE` 词表放得太宽**：「冲动 / 忍不住」放进强情绪词后，「冲动买了个包 300」被当成树洞、不入账。移出 `EMOTE`，只留在 `IMPULSE` 里且必须配 `REGRET` 才成立——**动作词不等于情绪词**。
3. **`rebundle.py` 不会自动插入新模块块**：`MODULES` 加了 `voice.js` 只保证「已存在的块会同步」，HTML 里没有对应 `<script>` 块就等于没加载。需手工按 `* tone.js` 声明锚点 + 首个 `</script>` 定位插入，再跑 `--check` 确认漂移 0（30 模块 + 1 样式）。
4. **模型「只给选项不写正文」时，正文是本地套话**：全量回归里「看看这几笔都是什么」被答成「挑一个，我接着办。」——那是 `agentParsePlan` 在 `final` 缺失时补的引导句，一个字事实都没有，而卡上明摆着「餐饮 3 笔：食堂 12、黄焖鸡 18…」。修法是给这句套话打 `fillerFinal` 记号：这一轮若前面已经跑过工具且没执行新动作，就用最后一条成功工具的 `brief` 顶掉它（同时不让套话进 `deferredFinal` 队列）。**本地补的兜底文案，只要带不出事实，就该在拿到事实后让位。**

## 2026-11-03 · 深度思考别把一句话说三遍

用户截图：展开「智能体」思考卡后，面板里 `想：这句不用查账，直接答` 和卡面预览句一字不差；`答：行，那我先待着…` 又和下方气泡重复；「1 轮」在按钮小标、面板标题、轮次标题里各出现一次；更扎眼的是 `1 轮 · 共 12.1s` 和 `第 1 轮 1.4s` 两个数字自己打架。评价是「深度思考效果呈现不行，且重复说明了」。

**根因不是样式，是同一份数据被渲染了三遍**：

1. 卡面预览句（`.agent-thought`）、外层步骤列表（`.agent-steps`）、展开面板（`.agent-deep`）都从同一份 `rounds` 取数，展开时三层同时在场。
2. 面板固定按「第 N 轮 / 想 / 答」网格渲染——只有一轮时，这三样都是占位符，没有信息量。
3. 纯文本兜底分支里塞了一句**假想法**：「这句不用查账，直接答」。它既不是模型想的，又和答复同义，是三重重复里最刺眼的一条。

**改法（`agentTrace` / `renderDeep`）**：

- **展开即收起**：面板一打开，卡面预览、步骤列表、按钮小标同时收起（用内联 `display`，因为 `.agent-steps` 自带 `display:flex` 会盖掉 `[hidden]`），关上再还原。同一件事不在同一张卡里说两遍。
- **单轮不写轮次标题**：meta 按形态换口径——一问一答 `直接作答 · 1.4s`；调过工具 `调了 2 个工具 · 共 4.2s`；多轮 `2 轮 · 1 个工具 · 共 5.1s`。
- **「答」按内容去重**：把气泡里最终显示的话传给 `finish(calls, shownText)`，末轮原话去标点后若包含/公共前缀过半，就不再重贴，只留一行 `答 见下方的回复`；真有改写（`agentVoice` 去 AI 味）才贴 `原话` 供对照。
- **纯文本兜底不再编想法**：改为 `想`（空）+ `做 没调工具，直接开口回话`，只记录真实发生的事。
- **两个耗时都给出解释**：整轮比模型耗时多 1.5s 以上时补 `· 整轮 12.1s`，让用户知道多出来的时间在哪，而不是看着两个数字互相矛盾。`AJ_AGENT_LOG()` 同步加 `timing`（整轮 + 每轮模型耗时），下次再报「数字对不上」可直接查日志定位。
- **顺手修本地卡的自述**：`localPlanOf` 的「依据」行原来非记账一律写「这句话本地就能判定，先看依据」，等于没说；改为按意图自报家门（`闲聊一句，不用查账` / `问的是账本里的数，本地能算…`）。

**验证**：`node test/eval_e2e.js` 14/14（新增第 11 条「深度思考不重复说明」：展开后预览必须收起、面板不得复述气泡、一问一答不得出现「第 1 轮」、meta 必须说清这轮做了什么），规则层 51/51，`rebundle.py --check` 双产物漂移 0。

## 2026-11-02 · 深度思考开关（可解释性）

思考卡原本只有「一句话 thought + 步骤列表」：看得出它做了几步，看不出每步**为什么**做、**传了什么参数**、模型**原话**是什么。用户要求「让用户知道 AI 怎么思考回答的」，故在卡底加一个开关。

- **按轮次摊开推理链**：每轮给出 `想 → 调了哪个工具（含入参）→ 拿回什么 → 答`，轮次带模型耗时、面板头带「N 轮 · N 个工具 · 共 N.Ns」。
- **采集口径改了**：`thought` 原来截 60 字且只留首轮（末轮常与回复重复），现放宽到 200 字并按轮落库；`agentExec` 补记工具入参（`agentArgsPeek` 压成 `scope=month category=餐饮` 一行）与执行耗时。
- **计时修正**：首版用「两轮之间的间隔」，实测末轮显示 `0.0s`（因为计时从 think 开始，而 think 在模型已返回后才调用）。改为从发起请求掐到拿回计划，现在每轮报的是真实的模型思考耗时（实测 1.4~2.4s）。
- **模型原话留档**：`answer()` 记的是 `agentVoice` 改写前的 `final`，用户可对照最终回复看出人设后处理改了哪儿。
- **默认收起**：可解释性要随手可得，但不能让推理过程把聊天顶走；结束时按钮旁挂「N 轮」小标，点了才展。运行中也可点开实时追加。
- **验证**：端到端新增第 10 条用例「深度思考面板还原推理链」（断言默认收起、按轮展示、含想法与工具结果、含总耗时），`node test/eval_e2e.js` 10/10；规则层 51/51；浅色与深色截图各验一次。

## 2026-11-02 · 明细查询口径对齐（截图反馈）

用户截图：上一句「本月餐饮 3 笔 一共 253」，点「看看这三笔都是什么」后查出「7 笔 · 支出合计 ¥445.00」——同一件事两个数，模型还只复述了「看了下：7 笔，支出合计 ¥445.00」。

- **根因一（缺参数）**：`list_bills` 只有 category/keyword，没有时间范围，查不了「本月」，只能扫全账本。
- **根因二（口径不自洽）**：笔数把收入也算进去、合计只算支出，所以「7 笔 · 445」自身就不成立。
- **根因三（指代靠模型自觉）**：`agentLastScope` 上线前，「这三笔」要模型自己把 category 带过去，漏传就查全账本。现改为服务端兜底：`get_spending` 记下本轮范围与品类，`list_bills` 在出现「这几笔 / 那三笔 / 它们」等指代词时自动继承（10 分钟内有效），无指代词则不继承，避免「我最近都买了啥」被上一轮品类限死。
- **brief 带内容**：原来 brief 只有「N 笔 · 合计 X」，模型除了复述数字无话可说；现在带每笔名字与金额（最多 6 条），回复能说清「这三笔是外卖麻辣烫 26、黄焖鸡 18、饭卡充值 220」。
- **提示词**：硬规则 19 —— 指代必须沿用上一轮范围与品类，拿不准先问；`list_bills` 之后 final 要说清钱花在哪，不许只复述卡片数字。
- **验证**：端到端评测新增两条多轮用例（指代追问口径一致 / 无指代词不误继承），`node test/eval_e2e.js` 9/9；规则层 51/51。

## 2026-10-31 · 冷静卡「问太多」（用户两张截图：「AI问太多了」）

用户实测：说「烧烤 50」→ 弹出剁手冷静法卡，问要不要等 24 小时 → 他明确回「不用等，现在就想吃，帮我记上」→ **又弹了一张冷静卡**，还又问「你先选一下：先挂在冷静清单，还是确认现在这顿照样记账」。同一件事被问了两次，钱还没记上。

### 根因：这句话被当成了「新一轮想买」

消息入口的顺序是「命令 → 跳转 → 模糊澄清 → 智能体」。用户那句回答不属于任何一条，于是落到智能体；模型看到「想买烧烤」+ 金额 50（等于冷静阈值），按提示词第 3 条「≥ 阈值必须先调 cooling_check」又开了一张卡。**提示词把「大额必须先开卡」写成了无条件规则，没有「用户已经拒绝过」这个例外；工具层 `cooling_check` 也没有任何确认口径**——`add_bills` 里早就有 `isConfirmRaw` 放行「记上/确认/没记错」，但冷静卡这条路没享受到。

### 改法：三层，从硬到软

1. **消息入口加前置快路径**（`tryResolvePendingAdd`，在所有意图判断之前）：冷静卡或冷静期还挂着时，用户这句话就是在回答它，本地直接了结，根本不进模型。拒绝类语义 → 入账；放弃类语义 → 省钱 + 心愿单。语义判定用一组共用正则（`coolingRefused` / `coolingGivenUp`），问句一律不抢（「冷静期还有多久」是在问，不是在做决定），「不买」优先于「要」。
2. **工具层兜底**：同一笔的冷静卡还在等决定时，`cooling_check` 不再开第二张；若用户这句明显是拒绝，直接按记账办，并把「别再开卡、别让用户二选一」写进返回给模型的 note。
3. **提示词**：硬规则第 3 条加例外（已明确说「现在就买/不用等/帮我记上/确定要」→ 直接 `add_bills`）；第 6 条补「卡片上已经有按钮时，final 不要再把同样的选择问一遍，choices 留空」。

### 顺带修掉的两个真问题

- **烧烤被记成「购物」**：`coolingRecord()` 的品类原来写死 `'购物'`，而剁手冷静法会被夜宵、火锅、奶茶触发。改为按商品名过 `NLP.classify` + `agentCategory`，实测烧烤归「餐饮」。这影响账单分析分类占比和恩格尔系数——记错品类比多问一句更隐蔽。
- **过期卡误接管**：冷静卡开卡加 `ts`，超过 5 分钟就不再接管自然语言，避免用户很久之后说「算了」（说的是别的事）被当成本笔放弃。只「不接管」，不销毁会话——卡片还挂在屏幕上，按钮必须还能点。

## 2026-11-02 · 新手引导「框区不准」修复（用户截图：理财专家步高亮框与卡片错位）
